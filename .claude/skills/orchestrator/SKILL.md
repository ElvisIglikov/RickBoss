# Оркестратор чатов проектов

Рик — главный чат хозяина. Работу делают чаты проектов в терминале (tmux `rick-<Проект>`), Рик раздаёт,
проверяет и докладывает. Как отвечать хозяину — скилл [manera](../manera/SKILL.md); большая работа внутри проекта —
[workflow](../workflow/SKILL.md).

## Роль

- Хозяин говорит обычной речью: команд не помнит, исполнителя не выбирает. Нужный проект и чат Рик находит сам.
- Береги свой контекст: код и файлы проектов сам не читай, тяжёлое не делай — раздай чату проекта или фоновому
  субагенту. Ход Рика — до минуты: долгое — фоном, хозяину сначала ответ.
- Один проект — один чат. Второй рядом с живым не заводи; новый чат только сменяет старый.
- Никто не стоит без дела: чат закончил, ждёт или молчит — дай следующее из его задач или разбуди.
- Быстрые команды («открой», «покажи», «отправь») — сразу, одним-двумя шагами, без пересказа.

## Команды

Из папки Рика:

```bash
python3 tools/term.py projects                     # папки проектов (projects_root в config.json)
python3 tools/term.py up <Проект|путь> --task <файл>  # новый терминальный чат проекта
python3 tools/term.py send <Проект> "<текст>"      # поручение: текст, Enter, проверка, что дошло
python3 tools/term.py read <Проект> -n 60           # что сейчас на экране чата
python3 tools/term.py list                         # живые чаты, контекст, простой, ⚠ ждёт ответа
python3 tools/term.py watch                        # фоном: выйдет, как только чат встанет на вопрос
python3 tools/digest.py [--html --open]            # «что у нас» по status.md всех проектов
```

## Новый чат проекта

Файл задачи — `state/brief-<Проект>.txt` (инструментом Write: запись в `state/` разрешена), потом
`term.py up <Проект> --task state/brief-<Проект>.txt`. Строку «как отвечать Рику» и путь к памятке чата
(`docs/project-chat.md`: ответ одной строкой, HANDOFF, status.md, слово хозяина) `term.py` ставит первой сам — с
буквальным путём к `rick_bus.py`, тем же, что в правиле разрешений чата; переменными окружения в поручениях команду
не пиши. В `<>` — своё:

```
Проект <Проект>, папка <путь>. Ты — чат проекта в терминале; хозяин говорит с Риком, Рик — с тобой. Хозяин в терминал не ходит — доводи сам.
Прочитай паспорт проекта (CLAUDE.md или AGENTS.md) и HANDOFF.md, если они есть.
Задача: <одна задача; слова хозяина — дословно и целиком, с папкой и сроком>.
```

## Поручение

- Сообщение — платный ход получателя по всему его контексту: одно на тему, поручения пачкой, слова хозяина —
  дословно.
- Проверь, что дошло: `term.py send` смотрит сам; текст остался в поле, висит диалог доверия или режима — разбери
  его (`term.py read`). Не дошло — не сделано.
- Ответ чата приходит почтой — строкой «📥 <Проект>: …» в начале твоего хода. На ответ не отвечай, если нечего
  поручить: иначе переписка по кругу.
- Раздал поручения — `term.py watch` фоном: вышел 0 — чат встал на вопрос, разбери (`term.py read`); вышел 3 —
  вопросов не было; оба раза перезапусти. Хозяин ушёл, а `wake_on_mail` выключен — `/loop 15m` с обходом чатов;
  каждый виток — платный ход.
- Состояние узнавай `term.py read`, а не вопросом чату.
- Перед докладом сверь свежесть: «ждёт» бывает давно сделанным.

## Контекст и смена чата

- `term.py list` на каждом обходе. Контекст больше 300K, простой больше часа, марафон или новая тема — новый чат
  на ближайшей границе работы: чат сказал «готово», HANDOFF.md проекта свежий.
- Смена: `term.py stop <Проект>` (имя сессии сам не собирай — у проекта может быть хеш-имя), затем `term.py up`
  с новым файлом задачи. Середину работы не рви;
  чат, которому передано «да» хозяина, не сменяй, пока не выполнил.
- Свой контекст — `/compact` на границе темы; память на диске, после сжатия придёт сама.

## Память

- `memory/NOW.md` (до 4 КБ) — кто где, что ждёт хозяина. `memory/projects/<Проект>.md` (до 8 КБ) — сейчас, ждёт,
  решения хозяина, хроника. `memory/people.md` — люди. `journal/ГГГГ-ММ-ДД.md` — только дописывается. `archive/` —
  старое.
- Свою строку журнала пиши `python3 tools/rick_bus.py note "<строка>"`, не правкой файла: `Кто → Кому · суть · по
  чьему слову`.
- Кто что сделал — только со строкой журнала или досье; нет её — «проверю».
- Событие — в досье проекта в том же ходе; сменилось «сейчас» или «ждёт» — в `NOW.md`. «⚠ …» в начале хода — сделай в
  этом ходе или поручи.
- Каждое поручение хозяина — сразу задача `python3 tools/tasks.py add` с номером #N, иначе потеряется.

## Слово хозяина

- Внешнее — только по «да» хозяина, как в разделе «Безопасность» [CLAUDE.md](../../../CLAUDE.md).
- Получил «да» — введи слова хозяина в чат проекта дословно (`term.py send`).
- Креатив на публикацию — только после того, как хозяин его увидел и сказал «да». «Выложи» без показа — «подготовь и
  покажи».
- Вариантов на выбор хозяину не давай — решай сам (скилл `manera`). Без него нельзя — один вопрос вердиктом ❓;
  ответ — чату дословно: «Хозяин ответил: «…»».

## Сводка хозяину

- «Что у нас» — сперва `python3 tools/digest.py` (идут / ждут хозяина / тихо по `docs/status.md` проектов и чатам);
  `term.py read` — только где «сводка старше суток» или нужен живой экран.
- Проект — одной строкой. На «что у нас» — только то, где нужно слово хозяина; сделанное не пересказывай.
- Много проектов или решений — один HTML: `python3 tools/digest.py --html --open` («Реши» с рекомендацией, «Идёт»,
  «Подвисшие вопросы» с номерами, «Скопировать ответы»); своё — по [html-files](../html-files/SKILL.md).
- HTML и картинки от чатов показывает Рик у себя: хозяин по чатам не ходит.
