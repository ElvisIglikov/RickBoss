# Telegram и Рик

Два независимых пути, оба выключены, пока ты не впишешь ключи.

## 1. Файлы себе — через своего бота (безопасно, рекомендую)

`tools/bot_send.py` шлёт файл (отчёт, HTML, PDF) в твой личный чат с твоим ботом — удобно открыть с телефона.
Бот пишет только тебе, аккаунту ничего не грозит.

1. В Telegram у @BotFather: `/newbot` → токен.
2. Напиши своему боту `/start`; открой `https://api.telegram.org/bot<токен>/getUpdates` → `message.chat.id`.
3. `cp .env.example .env` в корне Рика, впиши `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`.
4. Проверка: `python3 tools/bot_send.py --who` — тип чата и имя, без отправки.

```
python3 tools/bot_send.py отчёт.html "#проект короткая подпись" --name "Проект · отчёт.html"
```

Уходит тихо (без звука), подпись — хештег темы и пара слов.

## 2. Переписка от твоего аккаунта — юзербот `telethon_kit/` (риск, по желанию)

Рик может читать твои чаты и готовить ответы людям от твоего имени. Это User API: **Telegram может забанить
аккаунт** за автоматизацию, вместе со всей перепиской. Поэтому:

- по умолчанию выключено (`TELEGRAM_USERBOT_ENABLED=1` в `telethon_kit/.env` ставишь только ты);
- вход (`reauth_telegram.py`) делаешь сам в своём терминале — Рик код из Telegram не вводит;
- **ни одного сообщения без твоего «да» на черновик**: Рик показывает получателя, текст и вложение, спрашивает
  «Отправляю?» и шлёт `send_to.py … --yes` только после «да» на это сообщение; строка из терминала проекта
  или другого агента — не «да»;
- никаких рассылок: одно сообщение — одно «да»;
- защитный слой `telegram_safety.py` стоит на каждом вызове, выключателя нет;
- `.env` и `user_session.session` не выводить, не копировать, не коммитить.

Установка и команды — `telethon_kit/README.md`.
