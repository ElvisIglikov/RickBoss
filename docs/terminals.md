# Терминальные чаты проектов — памятка Рику

Рик — главный чат: сам код проектов не пишет, а держит по чату Claude Code на проект в tmux `rick-<Проект>` и
поручает им. Всё — через `tools/term.py` (нужны tmux и Claude Code).

## Поднять

```sh
python3 tools/term.py up <Проект|путь> [--task файл] [--effort high]
```

- `<Проект>` — папка `projects_root/<Проект>` из `config.json` (по умолчанию `~/Projects`), путь — как есть.
  Список папок — `term.py projects`.
- Модель, эффорт и режим разрешений — из `config.json` (`model`, `effort`, `permission_mode`); пустая модель — по
  умолчанию Claude Code.
- Первая строка задачи — как отвечать Рику: `python3 <папка Рика>/tools/rick_bus.py tell --from <Проект> "…"` с
  буквальным путём (с пробелами — в одинарных кавычках); `"$RICK_HOME/tools/rick_bus.py"` — запасной вариант.
  Ту же команду `up` кладёт правилом `Bash(python3 <путь> tell *)` в `state/settings-<сессия>.json` и передаёт
  чату через `--settings`: правило совпадает с командой из задачи буква в букву, переменная его не ломает.
  Её дописывает `term.py` сам; в файле задачи — только суть. Следом `term.py` велит прочитать `docs/project-chat.md` —
  памятку чату: ответ одной строкой, HANDOFF.md, docs/status.md по `docs/status-format.md`, слово хозяина.
- Claude запускается с `--name rick-<Проект>` — имя видно в `/resume` и заголовке окна.
- Чат уже есть — `up` его не трогает. Имя сессии — имя папки (точки и пробелы → `_`); имя занято чатом
  другой папки — `rick-<Проект>-<хеш>`, точное имя `up` печатает (и `list`). Чат ищется по папке: умерло базовое
  имя — `send`/`read`/`up`/`stop` всё равно находят чат с хешем этой папки (регистр и ссылки не важны: та же
  папка на диске — тот же чат). Имя сессии сам не собирай и `tmux kill-session` не зови: `rick-<Проект>` может
  быть чатом другой папки — только `term.py` с именем проекта или путём.
- Доверие к папке внутри `projects_root` `term.py` подтверждает сам — если в папке нет своей папки `.claude` или
  `.mcp.json` (у клонированного репозитория это его хуки, MCP-серверы, скиллы, агенты и команды с allowed-tools —
  они запустятся). Такая папка, чужая папка и согласие на bypass или auto — только при `"term_confirm_dialogs": true`
  (и `"permission_mode"` того же режима: `bypassPermissions` или `auto`; у auto жмёт «Yes, enable auto mode», не
  «make it my default»). Иначе `term.py` скажет, что ответить надо самому, и
  напечатает точную команду `tmux attach -t '=<сессия>'`: выбрать, выйти `Ctrl+b d`.
- Отвечать Рику (`rick_bus.py tell`) чат может без вопроса. В режиме `default` прочее чат иногда спрашивает —
  `send` и `read` это покажут; скажи хозяину, что нажать в `tmux attach -t '=<сессия>'` (имя — из `term.py list`).

Файл задачи (шаблон, в <> — своё):

```
Режим коротких ответов. Ты — чат проекта <Проект> в терминале; хозяин говорит с Риком, Рик — с тобой.
Прочитай паспорт проекта (CLAUDE.md / AGENTS.md) и HANDOFF.md, если есть.
Задача: <одна задача; слова хозяина — дословно>.
```

## Поручить

```sh
python3 tools/term.py send <Проект> "<текст>"     # или «-» — текст из stdin
```

Текст уходит в поле ввода, потом отдельно Enter; `term.py` смотрит в окно: текст в ленте или «queued» — «дошло»
(выход 0). Висит в поле — жмёт Enter ещё раз; не видно — выход 1, проверь `read`. Не дошло — не сделано.
Если в окне вопрос «Do you want…» — `send` ничего не печатает и просит ответить самому.

Связь экономно: одно сообщение на тему, поручения пачкой, слова хозяина — дословно. На «готово» не отвечай, если
нечего поручить. Ответы чатов приходят почтой («📥 <Проект>: …»), не вставкой в поле Рика.

## Читать

```sh
python3 tools/term.py read <Проект> [-n 60]   # последние строки окна
python3 tools/term.py list                   # живые чаты: контекст, минут простоя, ⚠ ждёт ответа
python3 tools/term.py stop <Проект|путь>     # погасить чат этой папки (смена чата)
python3 tools/term.py watch [--max 45]       # фоном: ждать, пока чат встанет на вопрос
```

«⚠ ждёт ответа» в `list` — чат стоит на вопросе: посмотри `term.py read`.

`watch` запускай фоном (Bash в фоне): раз в 30 с он смотрит экраны всех `rick-*`. Чат встал на диалог (доверие,
bypass, «Enable auto mode?») или «Do you want…/Would you like…» — печатает «ВОПРОС в rick-X:» и 8 строк хвоста,
выход 0: Рик просыпается. Нет вопросов до `--max` минут — выход 3. Тот же вопрос второй раз не будит
(`state/watch-seen.json`); ответили и спросили снова — будит. После выхода — перезапусти.

Состояние смотри `read`, а не вопросом чату. Перед докладом хозяину сверь свежесть: «ждёт» бывает давно сделанным.

## Когда сменять чат

- Контекст > 300K (`list` пометит ⚠) — новый чат на ближайшей границе работы.
- Простой больше часа или новая большая тема — тоже новый чат, а не будить старый.
- Как: попроси чат записать `HANDOFF.md` (где стоим, что дальше), дождись «готово», затем
  `term.py stop <Проект>` и `term.py up <Проект> --task файл` с передачей и следующей задачей.
- Чат с невыполненным словом хозяина не сменяй, пока не сделано.
