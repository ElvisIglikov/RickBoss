# telethon_kit — Telegram от твоего аккаунта (по желанию, выключено)

Маленькие CLI-скрипты, которыми Рик читает и пишет в Telegram от имени ОБЫЧНОГО аккаунта (юзербот,
Telethon, User API): лички, группы, файлы, ответы цитатой.

## Сначала прочитай

- **Риск бана аккаунта.** Telegram банит за автоматизацию на User API целиком, вместе с перепиской.
  Массовые рассылки, частые вызовы, новые аккаунты — верный путь. Пользуйся, только если готов к этому риску.
- **По умолчанию выключено.** Пока в `telethon_kit/.env` нет `TELEGRAM_USERBOT_ENABLED=1` и ключей, ни один
  скрипт не подключится.
- **Ни одного сообщения без «да» хозяина на черновик.** `send_to.py` без `--yes` ничего не отправляет — печатает
  черновик. Рик показывает получателя, текст и вложение, спрашивает «Отправляю?» и ставит `--yes` только после
  твоего «да» именно на это сообщение. «Да» на одно не переносится на следующее. Ответ, пересылка, отложенная
  отправка, правка — тоже сообщения.
- **Защитный слой обязателен** (`telegram_safety.py`): ставится на клиент при создании, выключателя нет —
  1 с между вызовами, дневные квоты, память о FloodWait между запусками, журнал вызовов.
- Файлы себе в Telegram юзербот не нужен: для этого есть `tools/bot_send.py` через своего бота — безопасно.

## Что внутри

| Файл | Что делает |
|---|---|
| `telegram_user_client.py` | Ядро: `.env`, клиент Telethon, защитный слой. Все скрипты берут `client` отсюда. |
| `telegram_safety.py` | Защита аккаунта: темп, квоты, FloodWait, журнал `.telegram_safety/api.log`. |
| `telegram_safety_status.py` | Квоты за сегодня; `--reset` — сбросить счётчик, `--clear-floodwait` — снять паузу (осторожно). |
| `reauth_telegram.py`, `qr_login.py` | Первый вход: телефон и код или QR. Создают `user_session.session`. |
| `tg_dialogs.py` | Список чатов с id: `--filter <название>`, `--kind dm\|bot\|group\|channel`, `--unread`. |
| `read_from.py` | Последние N сообщений чата, с файлами и «ответ на #N». |
| `send_to.py` | Отправка текста или файла — только с `--yes`, после проверок `send_hooks.py`. |
| `send_hooks.py` | Проверки перед отправкой: запрещённые получатели, несовпадение имени и id, пути, markdown. |

## Включить (10 минут, делает хозяин)

1. Зависимости в отдельное окружение:
   `cd telethon_kit && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt`
2. Ключи приложения: https://my.telegram.org → API development tools → создать приложение. Это ключи ТВОЕГО
   аккаунта — никому не показывать.
3. `cp .env.example .env`, вписать `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`, поставить `TELEGRAM_USERBOT_ENABLED=1`.
4. Вход — в СВОЁМ терминале (нужен код из Telegram): `.venv/bin/python reauth_telegram.py`
   (код не приходит — `.venv/bin/python qr_login.py`). Напечатанный id впиши в `.env` как `TELEGRAM_MY_ID`.
5. Появится `user_session.session` — это ключ от аккаунта: не копируй на другую машину, не клади в git.

Свои данные — только в `team_config.json` по образцу `team_config.example.json` (он в .gitignore, в коде пусто):
`aliases` — короткие имена получателей, `team` — сверка «id ↔ человек», `never_send` — кому писать нельзя никогда.

## Работа

```
.venv/bin/python tg_dialogs.py --filter работа          # найти id чата
.venv/bin/python read_from.py <id> --limit 20           # прочитать
.venv/bin/python send_to.py <id> --stdin < draft.txt    # черновик: показать хозяину
.venv/bin/python send_to.py <id> --stdin --yes < draft.txt   # после его «да»
.venv/bin/python read_from.py <id> --limit 2            # проверить, что ушло
```

- Текст людям — текстом через `--stdin`, не аргументом (кавычки и `--` съедают текст). Больше 4096 символов —
  резать по абзацу. `--file` — только когда нужно именно вложение.
- Без `##`, блоков кода и таблиц: Telegram покажет их как есть.
- Одна сессия — одна машина — один процесс за раз, иначе `AuthKeyDuplicated` и разлогин.
- Не гонять `tg_dialogs.py` в цикле и не выкачивать все чаты подряд: известный id — сразу `read_from.py`.

## Типовые ошибки

- `Could not find the input entity` — чата нет в кеше сессии: прогони `tg_dialogs.py` или адресуй `@username`.
- `FloodWaitError` / `FloodWaitActive` — Telegram просит подождать; слой это запомнил. Ждать, не перезапускать.
- `QuotaExceeded` — дневная квота: скорее всего, зациклился скрипт. Разберись, прежде чем `--reset`.
